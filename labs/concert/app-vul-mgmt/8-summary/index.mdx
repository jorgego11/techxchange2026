## Recap: What You Accomplished

Over the course of this lab you took an application from unknown to secured, using IBM Concert to do the heavy lifting across the entire application vulnerability lifecycle.

You started by **building and scanning an application with IBM Bob**, generating a Java Maven project from a plain-English prompt, introducing known-vulnerable dependencies, and running it through Concert's scan pipeline. You then used **GitHub auto-discovery** to connect a repository, let Concert scan its code and dependencies, and reviewed the findings ranked by how much risk each one actually poses in *your* environment. Optionally, you extended that same discovery flow to a **Red Hat OpenShift cluster**, scanning the container images actually running in production. Finally, with **Auto-Remediation**, you let Concert Secure Coder generate the fix itself — cloning the repository, producing a remediation plan with a compatibility analysis, applying the dependency upgrades, and opening a pull request, all without writing a line of code.

That end-to-end flow — **discover → prioritize → remediate → verify** — is exactly what Concert automates in real environments, at far greater scale.

### The Value of IBM Concert for Application Vulnerability Management

IBM Concert transforms application vulnerability management from a fragmented, manual process into a centralized, AI-orchestrated workflow.

By aggregating data from source repositories, container registries, running clusters, and CVE feeds, Concert builds a contextual view of your entire application landscape. Rather than a blunt "fix every CVE" approach, it uses generative AI to prioritize remediation based on real risk — combining CVSS severity, exploit prediction, and the business criticality and data sensitivity *you* assign to each application — so the vulnerabilities that actually matter are addressed first.

The platform provides significant operational value by automating the full lifecycle: discovering applications and their dependencies, scanning them for vulnerabilities, prioritizing findings by environment-aware risk, and remediating them with AI-generated code changes delivered as reviewable pull requests.

#### Key Benefits

- **Risk-Based Prioritization:** Instead of chasing thousands of raw CVEs, Concert turns them into a short, ranked list of what to fix first — using severity, exploitability, and the criticality of the application each finding lives in. The same CVE can be urgent in one app and deprioritized in another, and Concert tells you which is which.
- **Full Blast-Radius Visibility:** Concert traces each vulnerability from the CVE, through the package that carries it, to every repository, image, application, and environment it reaches — so you can see whether a single fix clears one finding or resolves the issue across several applications at once.
- **AI-Assisted Remediation:** With Secure Coder, Concert does not just tell you what to fix — it writes the fix, validates it with a compatibility analysis generated by watsonx.ai, and opens a pull request, closing the loop from finding to reviewable code change.
- **Meets Developers Where They Work:** Findings become tracked tickets and pull requests in the tools developers already use, with remediation guidance written in — no copying by hand, and no context lost between security and engineering.

Through this combination of risk-aware prioritization and automated, AI-generated remediation, IBM Concert strengthens the security posture of your applications while shrinking the window of exposure to critical vulnerabilities.
